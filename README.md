# IT爱学堂-【Harness&amp;Hermes】多智能体开发特训营（完结）
获课：aixuetang.xyz/23627/

定位与分工——Harness 是执行框架，Hermes 是自主智能体
多智能体开发最容易走偏的第一步，是把 Harness 和 Hermes 当成同一层面的东西来比较。实际上，它们解决的是完全不同的问题。

Harness 的本质：Agent 运行时基础设施
Harness 不是一组提示词，而是一套有状态的 Agent 运行时。它向下管理模型采样、工具执行和沙箱隔离，向上通过协议层暴露给不同产品形态。OpenAI 公布的 Codex Harness 数据很直观：同一个模型，仅调整 Harness 配置——开启保留推理和上下文压缩——在 ARC-AGI-3 上的得分从 13.3% 跳到 38.3%，输出 token 还减少了 6 倍。模型没变，执行层变了，结果差三倍。这说明 Harness 对任务表现的影响，已经和模型本身同一量级。

Harness 的核心职责包括维护对话状态、组织模型与工具的循环、执行沙箱和审批策略、持续输出进度，以及让工作跨多轮延续。它用 Thread、Turn、Item 三个对象来组织 Agent 任务：Thread 表示一段可持久化、可恢复的会话；Turn 表示一次用户输入触发的 Agent 工作；Item 表示 Turn 内的原子输入或输出，如消息、推理、命令、文件修改等。这套状态管理机制解决的核心问题是：让任务跑上几个小时之后，仍能看见进度、补充输入、暂停审批、断开重连。

Hermes 的本质：自我进化的自主智能体
Hermes Agent 是 Nous Research 于 2026 年 2 月开源的自主智能体框架，采用 MIT 许可，GitHub Star 数已突破 10 万。它与 Harness 的根本区别在于设计哲学：Harness 是“你给 AI 造缰绳”，Hermes 是“AI 自己给自己造缰绳”。

Hermes 的核心创新是闭环学习系统，由三个子系统支撑：Memory 记录环境和用户偏好，Skill 从任务经验中自动提炼可复用的操作手册，Nudge Engine 定时触发自省并决定什么值得记住。Memory 系统的设计很克制：两个纯文本文件，MEMORY.md 限 2200 字符，USER.md 限 1375 字符。容量有限就迫使 Agent 挑重要的记，不重要的自然被挤掉，留下的都是高密度事实。

一句话理解两者关系
Harness 是导演和调度中心，负责编排多个 AI 角色像剧组一样分工完成复杂任务。Hermes 是通用语言和通信协议，让不同框架、不同厂商的 AI 能相互理解和配合。更准确地说：Hermes 更像一个智能体本身，Harness 更像支撑智能体运行的基础设施。特训营的第一阶段就是帮助学员建立这个清晰的定位认知，避免在后续实战中把编排逻辑和智能体能力混为一谈。
